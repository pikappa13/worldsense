# Project Name Options

The recommended name is `WorldSense`: it is short, memorable, agent-friendly, and broad enough for
future modules without sounding like a moderation-only tool.

| Name | Pros | Cons |
| --- | --- | --- |
| WorldSense | Memorable, practical, broad | May already be used in adjacent contexts |
| RealityEngine | Clear and ambitious | May overpromise simulation of reality |
| RealityGuard | Safety-oriented | Sounds more like a blocker than a reasoning layer |
| GroundLayer | Good technical metaphor | Less obvious to non-technical users |
| CommonSenseKit | Direct | "Common sense" can sound vague |
| SenseCheck | Simple and memorable | Could sound like a lightweight linter |
| RealCheck | Clear | Generic |
| WorldGuard | Strong for agents | May imply security-only use |
| CausalLayer | Research-friendly | More abstract |
| ConsequenceKit | Focused on consequences | Narrower than full vision |
| AgentJudgment | Very descriptive | Less elegant package name |
| ActionSense | Great for tool safety | Less suited to response checking |
| ContextBrake | Memorable for risky actions | Too negative for general use |
| Friction | Strong concept | Too generic and possibly negative |
| PracticalAI | Clear value | Very broad, likely unavailable |
| GroundTruthLayer | Clear grounding concept | Conflicts with factual truth framing |
| SafeAct | Good for agent actions | Too safety-specific |
| RealWorldCheck | Explicit | Long |
| Judgely | Brandable | Less technical |
| OpsSense | Good operational framing | Narrower than social/physical reasoning |
